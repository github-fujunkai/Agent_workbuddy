# 隐含问题解码 · 答题展开训练手册

> 病根诊断：你挂面试不是因为知识不够（知识包够了），是**没把"听题"当成技能练**。
> 面试官问得随意，因为提问不费力；他问一句，验收的是整条证据链——看你是不是真做过。

---

## 一、核心认知：每个问题都是一座冰山

- 他问**指标** → 想听指标的**传记**：怎么测的、踩过什么坑、波折、现状、失败模式
- 他问**方案** → 想听**决策过程**：为什么是它、备选是什么、什么约束、后来怎么演进、数据证明选对了吗
- 他问**成本** → 想听**钱的价值**：成本结构、合理性设计、业务价值、ROI
- 他问**观点/趋势** → 想听**证据**和与你项目的关联

一句话总纲：**他问"结果"，想听"过程"；问"点"，想听"链"。**

## 二、解码翻译表（听到左边的，心里自动展开右边的）

| 听到 | 完整问句（心里展开成 5-6 个子问题） |
|---|---|
| 用什么框架/方案？ | 为什么是它？约束是什么？备选为什么被否？后来演进了吗？评测数据证明选对了吗？你怎么分工？ |
| 成功率/准确率多高？ | 怎么测的？什么时候失败？典型 bad case 是什么？为什么错？怎么优化的、从多少到多少？ |
| 成本多少？ | 成本结构是什么？做了什么控制设计？带来什么业务价值？ROI 怎么算？ |
| 遇到最大困难？ | 怎么判断的？怎么取舍？怎么推动别人？结果和沉淀是什么？ |
| 怎么看 X 趋势？ | 你的观点？证据？和你做的项目什么关系？ |

## 三、万能六环展开法（答题骨架）

任何"点"问题，按六环展开，答完自检缺了哪环：

1. **结论**——先给干脆的答案（别绕）
2. **为什么**——约束和决策逻辑
3. **演进**——从什么到什么、为什么变
4. **证据**——数据 + 典型 bad case
5. **分工**——我定什么、谁做什么（AI PM 身份证明）
6. **价值**——ROI / 业务意义

口诀：**数字带传记，方案带决策，指标带失败模式。**

⚠️ 展开 ≠ 啰嗦：六环全，但每环一两句，90 秒讲完。**先给链，让面试官挑环追问，他挑中哪环你再展开哪环**——这叫"留钩子"，和背长篇是两回事。

## 四、三段示范逐字稿（用你的弹药，数字按真实情况替换）

### 示范 1："意图识别用什么技术框架？"

> "我们现在是大模型 few-shot 做意图识别，前面挂了硬规则做别名归一和敏感词拦截。**【结论】**
> 当时这么选有三个约束：涉密内网只能私有化部署、意图只有 9 个边界清晰、冷启动没有标注数据——prompt 方案一周上线，改规则当天生效。**【为什么】**
> 上线后在演进：靠 bad case 持续沉淀评测集，现在 300 多条，每版发布跑回归，误路由率从内测的 8% 压到 1.5%。后面时延或意图数量上来——比如复用到智能靶场时——会把一级分类换成微调小模型，大模型只处理低置信度的歧义请求。**【演进+证据】**
> 分工上，我定意图体系、边界和置信度三档阈值，算法负责选型和 prompt 实现——bad case 归因也干净：标准错了还是实现错了，一说就清楚。**【分工】**"

### 示范 2："skill 调用成功率多高？"

> "整体 96% 左右——但这个数字拆开讲才有意义。**【结论+拆解意识本身就是加分项】**
> bad case 集中在两类。第一类是意图边界混淆，最典型的是'借'和'领'：战士口语说'帮我弄点靶纸'，借和领分不清，早期出过误路由。修法分两层：skill 的 description 里写死负面边界——借用需归还、领用是消耗出账；置信度落在 0.5-0.85 之间不猜，反问确认。**【bad case 1 + 为什么错 + 怎么修】**
> 第二类是参数抽取错，比如'领 20 张'的数字归属模糊——skill 输入规范里规定：无法确定归属的数字不猜测，宁可追问。**【bad case 2】**
> 所有修复必须过评测集回归才能发版，有条铁律：通过率低于 95% 不发。有一次新版误路由降了但拒识率升了、老用户常用话术被拒答，被我拦下来折中后才放行。**【优化机制 + 拦版故事=做过的人才有的细节】**"

### 示范 3："日均模型 token 成本多少？"

> "我们是涉密内网私有化部署，成本结构和按 token 付费的公有云不一样——固定投入是 GPU 算力，所以我更关注**单位业务的资源效率**。**【结论+成本结构认知，先纠偏再回答】**
> 我盯两个指标：每次领用操作的模型调用轮数（控制在 4 轮）和上下文体积。压上下文靠三个设计：skill 索引层 description 控制在 100 字内常驻、skill 正文触发后才加载、RAG 知识库按需检索。**【合理性设计】**
> 换算成业务价值：单次领用 40 秒，替代原来约 15 分钟纸质流程，加上台账差错率和人力节省，年化的投入产出是能算清楚的一笔账。**【价值/ROI】**"

## 五、具体行动计划（每天 30-40 分钟）

**第 1-10 天：每天一题"解码训练"**（用作战计划里的 P0 十题）
1. 先写"完整问句"：这道题面试官真正想问的 5-6 个子问题（对照第二节翻译表）
2. 限时 5 分钟写六环答案（手写或打字都行，不许查资料）
3. 自检：六环缺了哪环？补上；数字记不清的标 `[补数字]`
4. 录音脱稿讲一遍，听自己有没有"答 A 就停"的地方

**第 11-12 天：追问树**
每题准备三层追问：面试官听完会接着问什么？他的追问会追问什么？（例：答完 few-shot → "为什么不用微调？" → "微调要多少数据？"）

**第 13-14 天：模拟压力面试**
找我当面试官，我故意问得短促随意（"成功率多少？""成本多少？"），你答完我数你漏了几环，再追问到你卡壳为止。

**日常心法（贴桌上）**：答完任何问题，问自己一句——**"他听完这句会追问什么？"然后提前把追问答掉。**

## 六、终极检验

哪天你听到"成功率多高"这种问题时，第一反应不是想那个数字，而是心里自动冒出六个子问题——这门技能就成了。
